- 2026-09-22: two false-alarm "critical regression" investigations, both resolved as the same test-methodology mistake: comparing a `--storage cache` (or zero-copy) run against a `--storage resident` baseline taken at a *different* `--n-batch`/`--n-ubatch`. Resident mode's own GPU kernel selection varies with batch size (confirmed resident-vs-resident alone diverges across batch sizes), and batches above a threshold are by design excluded from the small on-device cache and correctly run on CPU instead -- neither is a bug. With batch sizes matched on both sides, the classic cache, warm start (direct-I/O and mmap), and the zero-copy tier with and without bias are all bit-identical (tokens + logits hashes) to full-GPU resident, on both models.
