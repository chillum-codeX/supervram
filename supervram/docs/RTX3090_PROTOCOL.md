# RTX 3090 target-host protocol

## Prerequisites

- Linux host with RTX 3090, recent NVIDIA driver and CUDA toolkit.
- Local NVMe filesystem. Record whether it is ext4 or XFS and its mount options.
- Qwen3 MoE GGUF on the tested NVMe.
- Root access only if cold-cache runs are required.
- Optional GDS packages (`libcufile`, `gdscheck`) and `fio`, `iostat`, `perf`, `numactl`.

## 1. Capability probe

```bash
python3 scripts/probe_hardware.py --path /mnt/nvme --output results/3090-hardware-probe.json
nvidia-smi topo -m
sudo gdscheck -p
lspci -tv
find /sys/kernel/iommu_groups -maxdepth 2 -type l
```

A positive software probe is only a candidate. GDS must be verified with an actual cuFile read to a CUDA allocation. Record IOMMU, ACS, NVMe/GPU root-port topology, BAR1, Resizable BAR state, filesystem and mount options. Do not report direct SSD-to-VRAM DMA if cuFile falls back to compatibility mode.

## 2. Build

```bash
cmake -S third_party/llama.cpp -B third_party/llama.cpp/build-3090 -G Ninja \
  -DGGML_CUDA=ON -DLLAMA_BUILD_SERVER=ON -DLLAMA_BUILD_TESTS=ON -DGGML_CUDA_FA_ALL_QUANTS=ON
cmake --build third_party/llama.cpp/build-3090 -j "$(nproc)"
```

## 3. Baselines

Run at least:

1. Normal llama.cpp full-GPU when the model fits.
2. Normal layer split (`-ngl` reduced until it fits).
3. `--cpu-moe`.
4. `--moe-expert-storage mmap` from this patch.
5. `--load-mode mmap` and direct-I/O variants where supported.
6. Any implemented compact GPU expert-cache branch, clearly separated from the mmap baseline.

Use identical model file, quantization, context, batch, prompt, output token count, CPU affinity, power mode and clock policy.

## 4. Benchmark invocation

```bash
python3 scripts/benchmark_target.py \
  --server third_party/llama.cpp/build-3090/bin/llama-server \
  --model /mnt/nvme/qwen3-moe.gguf \
  --output results/mmap-warm.json \
  --server-arg=--moe-expert-storage --server-arg=mmap \
  --server-arg=-ngl --server-arg=all \
  --repetitions 10 --warmup 2
```

For cold-cache measurements, run a separate root-controlled experiment with `--cold-cache`. Never mix cold and warm observations in one aggregate.

## 5. Ablations

The requested Cartesian matrix is generated by:

```bash
python3 scripts/run_ablations.py --mode plan --output-dir results/ablation-plan
```

For a final GPU-cache implementation, execute cache sizes 4/8/12/16/20/22 GiB, prefetch depths 0/1/2/4/8, policies LRU/LFU/weighted/router-aware, and predictors none/history/router/Markov/lightweight/oracle. The plan contains 720 combinations; use blocked randomized order and at least five repetitions. Log skipped/OOM runs, never silently drop them.

## 6. Required counters

- llama-server timings: prompt tokens/s, decode tokens/s, TTFT proxy, TPOT.
- p50/p95/p99 request latency.
- `nvidia-smi`: utilization, VRAM and power.
- CUPTI/Nsight Systems for kernel/copy overlap and GPU idle gaps.
- `iostat -x 1`: NVMe bandwidth, IOPS, await, queue depth.
- `/proc/<pid>/status`, `smaps_rollup`, `pidstat`: RSS and CPU.
- SuperVRAM trace: cache hits/misses, prediction quality, reads and bytes/token, queue/read/copy/wait latency.
- Energy: integrate sampled GPU power and, when available, platform CPU/package energy.

## 7. Correctness gate

Before performance runs, compare deterministic token IDs and logits (within quantization/backend tolerance) against resident or standard CPU-MoE execution. Abort performance claims if outputs diverge.
